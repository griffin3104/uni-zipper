# uni-zipper 技術設計

> ステータス: ドラフト。要件は [機能要件.md](機能要件.md)、画面は [画面仕様.md](画面仕様.md) を参照。
> 「要検証」は、実装前または実装中にライブラリの挙動を確認する項目。

## 1. 全体構成

- **Tauri 2** を使う。
- **バックエンド(Rust)**: Zipの読み書き、文字コード判定・変換、正規化、ワークフォルダ管理、進捗通知、キャンセル。
- **フロントエンド**: 画面の状態管理、ドロップ受付、ダイアログ表示。Zipの処理はすべてRust側で行う。
- 処理は重いので、Rust側のコマンドは別スレッド(`spawn_blocking`)で実行し、UIを止めない。

```
[フロントエンド]                         [Rust]
 ドロップ(Tauriのドラッグ&ドロップイベント) ──パス一覧──→ add_items / inspect_zip
 保存ボタン ──────────────────────────→ compress(options)
 解凍ボタン ──────────────────────────→ extract(options)
 キャンセル ──────────────────────────→ cancel()
 ←──────── 進捗・完了・エラー(Channel / イベント) ────────
```

## 4. ワークフォルダ

- 場所: OSの一時ディレクトリ配下に、アプリ専用のディレクトリ + 実行ごとの一意なサブディレクトリを作る。
- 追加: ドロップされたパスを、ワークフォルダへコピーする(フォルダは再帰コピー)。
- **シンボリックリンクの拒否**: コピーを始める前に、ドロップされた全パスを `walkdir`(リンクを辿らない設定)で走査し、シンボリックリンクが1つでもあれば、**何もコピーせずに全体を拒否**する(途中まで追加された状態を作らない)。
- 同名の判定: ワークフォルダ直下の名前で行う。確認の結果は、上書き / 自動連番リネーム / キャンセル。
- 削除タイミング: 圧縮完了時、キャンセル時、エラー時、クリア時。
- **掃除**: アプリ起動時に、前回の異常終了などで残ったワークフォルダを削除する。
  - 場所は `<OSの一時ディレクトリ>/uni-zipper/run-<PID>-<時刻>`。
  - 別の起動(複数ウィンドウ)が使用中のものを消さないよう、**更新から24時間以上経ったもの**だけを削除する(自分のワークフォルダは対象外)。
- **実装**: `src-tauri/src/workdir.rs`。主なAPIは次のとおり。
  - `WorkDir::check_no_symlinks(paths)`: 全パスを走査し、リンクが1つでもあれば `SymlinkRejected`。ドロップ全体の拒否に使う(`add` でも自分の分を再検査する)。
  - `WorkDir::exists(name)` → 同名があれば、画面で上書き / リネーム / キャンセルを選ばせる。
  - `WorkDir::add(src, ConflictPolicy::{Overwrite, Rename})` → 最終的な名前を返す。途中で失敗したらコピーしかけたものを削除する。
  - `WorkDir::list()` / `remove(name)` / `clear()`、`Drop` で削除。
  - 連番は、ファイルは拡張子の前(`file_1.txt`、`archive.tar_1.gz`)、フォルダは末尾(`folder_1`)に付ける。先頭のドットは拡張子とみなさない(`.bashrc_1`)。
- 圧縮時は、ワークフォルダ内のフラットな内容をそのままZipにする。

## 5. 解凍の設計

### 5.1 エントリ名の解決

Zipのファイル名は、次の優先順位で決める。

1. エントリにUTF-8フラグ(一般目的ビット11)が立っている → **UTF-8**として確定。
2. Unicodeパス拡張フィールド(0x7075)がある → その値を採用する。**`zip` クレートが読み込み時に解釈して、名前をUTF-8に置き換え、UTF-8フラグ付きとして扱う**ので、自前の処理は要らない(7-Zipの実物で確認。5.8参照)。
3. どちらもない → 生のバイト列(`name_raw` 相当)から、下の判定を行う。

### 5.2 判定ロジック(フラグなしの場合)

全エントリのバイト列について、次の2つを試す。

| UTF-8として正しい | Shift_JISとして正しい | 結果 |
|---|---|---|
| はい | いいえ | UTF-8で確定 |
| いいえ | はい | Shift_JISで確定 |
| はい | はい | UTF-8として読んで**日本語が合計2文字以上**あれば、**UTF-8で確定**(下記)。1文字以下なら**曖昧** → プレビューで選ばせる |
| いいえ | いいえ | **曖昧**(読めない)→ プレビューで選ばせる(両方「化けた表示」になるので注意書きを添える) |
| 全部ASCII | - | 変換不要 |

**両方で正しく読めるときの補足(実装: `encoding.rs` の `detect`)**

- UTF-8の日本語は3バイト(`E3 83 95` など)で、Shift_JISの2バイトの組としても偶然成立しやすい。例: UTF-8の `ファイル.txt` はShift_JISとしても正しいバイト列になる。
- 単純に「両方正しい = 曖昧」にすると、Macで作ったZipのカタカナ名がほぼ毎回プレビューになる。そこで、UTF-8として読んで日本語(ひらがな・カタカナ・漢字・全角記号)が合計2文字以上あれば、UTF-8で確定する。Shift_JISのバイト列が、偶然UTF-8の3バイト列として何文字も揃うことはまず無いため。
- 「かなを必須にする」案も試したが、`写真/001.jpg` のような漢字だけの名前が約4割で曖昧になるため、採用しなかった。
- **検証結果**(ランダムな20万件ずつ。`cargo test` に含まれる):
  - ひらがな・カタカナ・第1水準漢字(日常の文字): 誤確定0件、曖昧0件。第1水準漢字の先頭バイトは `81〜98` で、UTF-8としては不正なので、混同しない。
  - 第2水準漢字を含む全漢字(意地悪な条件): Shift_JISの名前をUTF-8と誤確定したのが19件(約0.01%)、曖昧が1,588件(約0.8%)。UTF-8の名前をShift_JISと誤確定したのは0件。
- **既知の限界**: 珍しい漢字(第2水準)だけが並ぶShift_JISの名前は、ごくまれにUTF-8と誤確定する。

- UTF-8フラグ付きのエントリは判定の対象から外し、UTF-8として読む。残りのフラグなしのエントリで、1つの文字コードを選ぶ。これで、**1つのZipの中で文字コードが混在していても**(7-Zipは、Shift_JISに変換できない名前だけUTF-8フラグ付きで書く。5.8参照)、正しく読める。フラグなしのエントリの中で混在するケースは、まれなので考慮しない。
- Shift_JISは、`encoding_rs` の `SHIFT_JIS`(WHATWG仕様ではCP932相当のWindows-31J拡張)を使う。①②などのNEC特殊文字、丸数字、機種依存文字も読める。
- プレビューには、先頭数件のファイル名を、両方の読み方で表示する。

### 5.3 ファイル名の変換と正規化

- デコード後のファイル名を、**WindowsでもmacOSでもNFCに正規化**する(APFSはNFCでも問題なく扱える)。
- 実装: `src-tauri/src/normalize.rs` の `sanitize_entry_path(raw, platform)`。
- 展開先での無害化:
  - パス区切りは `/` に統一する。
  - **Zip Slip対策**: `..` や絶対パスを含むエントリは、展開先の外に出ないように検査し、危険なものはスキップする(スキップ一覧に載せる)。
  - **展開するOSがWindowsのときだけ**、次を置き換える(macOSでは、Windowsで使えない文字もそのまま使える)。
    - 使えない文字(`< > : " | ? *` と制御文字)は `_` にする。
    - 末尾の `.` と空白は、1文字ずつ `_` にする。
    - 予約名(`CON`、`PRN`、`AUX`、`NUL`、`COM1`〜`COM9`、`LPT1`〜`LPT9`。拡張子付きも)は、名前の部分の末尾に `_` を付ける(`CON.txt` → `CON_.txt`)。
  - NUL文字は、どのOSでも `_` にする。
  - 置き換えたファイルは、完了時にスキップ一覧と同じ形式で通知する(NFC正規化だけの変更は通知しない)。
  - `\` も区切り文字として扱う(古いZipは `\` を使う)。`.` と空の階層は取り除く。
  - 絶対パス(`/` や `\` で始まる、`C:` などのドライブ指定)と、`..` を含むパスは、展開せずスキップ一覧に載せる。
  - 正規化や置き換えの結果、同名になったら連番を付ける。
- 除外ファイル(`.DS_Store`、`__MACOSX`、`Thumbs.db`、`desktop.ini`)は、名前の判定で展開しない。`__MACOSX` はディレクトリごと除外する。

### 5.4 展開先フォルダ

- 場所: Zipと同じディレクトリ。
- 名前: Zipの拡張子を除いた名前。既にあれば `_1`、`_2` を付ける。
- 作成は、展開開始時に行う。キャンセル・エラー時は削除する。

### 5.5 パスワード付きZip

- **ドロップ時の判定**: セントラルディレクトリの暗号化フラグ(ビット0)、またはAESの拡張フィールドで判定する。
- 解凍時に、パスワードを使って復号する。
- **パスワード誤りの検出**:
  - AES: 検証値により、ほぼ確実に検出できる。
  - ZipCrypto: ヘッダの検証が1バイトだけなので、約1/256の確率で誤ったパスワードを通してしまう。**展開後のCRC32不一致も「パスワード誤り」として扱う**。
- 3回失敗で中止(画面仕様どおり)。

### 5.6 進捗・キャンセル・スキップ

- 進捗は、展開した総バイト数 / 全体の総バイト数(非圧縮サイズ)で計算する。通知は100ms以上あけて行う。
- キャンセルは、共有の `CancelToken`(`AtomicBool`)を、ファイルごと、および64KBごとに確認する。
- 読み書きできないファイルは、スキップして続行し、名前と理由を記録する。完了時にまとめて通知する。

### 5.7 実装(`zip_reader.rs` / `progress.rs`)

- `inspect(zip_path)`: ドロップ時に呼ぶ。エントリ数・暗号化の有無・文字コード判定の結果(曖昧なときはプレビュー付き)を返す。
- `extract(zip_path, options, on_progress)`: 展開本体。`options` は文字コード(`None` なら自動判定。決まらなければ `CharsetNotResolved`)、パスワード、展開先OS、`CancelToken`。
  - 文字コードを画面で選ばせた場合は、`Some(charset)` で渡して呼び直す。
  - 結果は `ExtractReport { out_dir, file_count, skipped, renamed }`。`skipped` は理由つき、`renamed` は元の名前 → 実際の名前。
- 処理の順序: ① エントリの一覧化 → ② 文字コード決定 → ③ 名前の決定(除外・無害化・危険なパスのスキップ・連番) → ④ **パスワードの事前確認**(展開先を作る前) → ⑤ 展開先フォルダ作成 → ⑥ 展開。
- エラー(`AppError`): `PasswordRequired` / `WrongPassword`(展開先は作られない・または削除される。UIが再入力させる)、`Cancelled`(展開先を削除)、`CharsetNotResolved`、`InvalidZip`。
- 失敗時の挙動:
  - 展開先フォルダは `OutDirGuard` が管理し、キャンセル・エラーで抜けると、作りかけを削除する。
  - ZipCryptoの誤パスワードが検証を通っても、復号結果が壊れてCRCが合わない / 解凍に失敗するので、**パスワード違い**として扱う(全体を止める)。
  - AESは、開く時点で誤りを検出できる。読み込み中の失敗は、**壊れたデータ**としてそのファイルだけスキップする。
  - 暗号化されていないZipでCRCが合わないファイルも、そのファイルだけスキップする(作りかけは削除)。
- 決めたこと:
  - **Zip内のシンボリックリンク**は、展開せず、スキップ一覧に載せる。
  - 除外ファイル(`.DS_Store` など)と、名前が空のエントリは、黙って無視する(スキップ一覧に載せない)。
  - 同じフォルダのエントリが複数あっても、1つにまとめる(連番は付けない)。ファイルは連番を付ける。
  - 同名の判定は**大文字小文字を区別しない**(macOS・Windowsでは `A.txt` と `a.txt` が同じファイルになり、上書きされてしまうため)。
  - 更新日時とファイルの権限は、**復元しない**(実行権限などを勝手に付けないため)。必要になったら検討する。
  - 展開先フォルダ名は、Zipのファイル名の拡張子を除いた部分をそのまま使う(正規化しない)。

### 5.8 実物のZipでの確認結果

新しいWindows 11で作った3つのZipのヘッダを調べた(`src-tauri/tests/fixtures/`)。

| | Windows 11 標準(`Folder.zip`、`win11_explorer.zip`) | 7-Zip(`win11_7zip.zip`) |
|---|---|---|
| 作成元(version made by) | `0x0314`(Unix、20)。従来のエクスプローラー(FAT = 0)とは違う | `0x003f`(FAT、6.3) |
| ファイル名 | **UTF-8、UTF-8フラグ(ビット11)あり**。フォルダ名も同様 | **Shift_JIS(CP932)、フラグなし**。ただし、Shift_JISに無い文字(波ダッシュ `〜`)を含む名前だけ、**UTF-8、フラグあり**(1つのZipに混在) |
| 拡張フィールド | `0x7875`(Unixの所有者)、`0x5455`(更新日時) | `0x000a`(NTFSの時刻)、フラグなしの名前には `0x7075`(Unicodeパス) |
| 濁点 | NFC(結合形) | NFC |
| その他 | ファイルは `0x0808`(データ記述子つき)。波ダッシュ入力 `〜` はそのまま(U+301C)で保存。全角チルダ `～`(U+FF5E)も別の文字として保存 | `①`、`㈱`(NEC特殊文字・機種依存文字)、半角カナも、Shift_JISで保存 |

- **新しいWindowsの標準機能は、UTF-8フラグ付きで書く**。「フラグあり → UTF-8」の処理で、そのまま正しく解凍できる(テストで確認済み)。
- **7-Zipは、Shift_JISで書く**(日本語環境の既定)。しかも、**Shift_JISに変換できない名前だけUTF-8に切り替える**ので、1つのZipの中で文字コードが混ざる。
  - UTF-8フラグ付きのエントリを判定から外す設計(5.2)のおかげで、混在していても、残りのShift_JISは正しく確定する。
  - 拡張フィールド(`0x7075`)があるZipは、`zip` クレートが名前をUTF-8に置き換えるので、判定自体が不要になる。7-Zipの既定のZipでは、こちらになる。
  - テストでは、拡張フィールドのIDを書き換えて無効にしたコピーでも確認し、**Shift_JISとしての判定・展開も実機のバイト列で正しく動く**ことを確かめた。
- 結論: **Shift_JIS名の実機Zip(7-Zip)で、期待どおりの展開を確認できた**。圧縮の「Windows」モード(Shift_JIS書き出し)は、7-Zipの日本語環境の既定と同じ形式になる。
- 圧縮の「Windows」モードは、この**7-Zip方式**(Shift_JISに変換できない名前だけUTF-8フラグ付き)で実装する(6.1で決定)。

## 6. 圧縮の設計

### 6.1 エントリ名

| 圧縮先OS | 名前のエンコード | UTF-8フラグ | 正規化 |
|---|---|---|---|
| 自動 | UTF-8 | 立てる | NFC |
| Windows | **エントリごとに決める**(下記。7-Zip方式) | Shift_JISの名前は**立てない**、UTF-8にした名前は**立てる** | NFC |

「Windows」の場合、エントリ名ごとに、次の順で書き方を決める(実物の7-Zipのバイト列に合わせた。5.8参照)。

1. NFCに正規化する。
2. **波ダッシュ `〜`(U+301C)を、全角チルダ `～`(U+FF5E)に置き換える**(CP932で対応する文字。Macで作った名前に出やすい)。置き換えたら「名前を変更した」扱いにして、完了時に通知する。
3. 全体をShift_JISに変換してみる(`encode_shift_jis_strict`)。
   - **変換できた → Shift_JISのバイト列で書く**(UTF-8フラグなし)。
   - **1文字でも変換できない → NFC後の名前を、そのままUTF-8で書く**(UTF-8フラグあり)。文字を `_` に置き換えることはしない。
4. 円記号 `¥`(U+00A5)とオーバライン `‾`(U+203E)は、`encoding_rs` が `0x5C`(`\`)・`0x7E`(`~`)に変換してしまい、`\` はパス区切りに化けて危険なため、**変換できない文字として扱う**(= その名前はUTF-8で書く。名前は変わらない)。全角の `￥`(U+FFE5)は、そのままShift_JISに変換できる。
5. 名前の変更(`〜` の置き換え)で同名になった場合は、`_1`、`_2` の連番を付ける。判定は、解凍と同じく大文字小文字を区別しない。
6. 判断は**エントリ単位**(フォルダの階層ごとではなく、パス全体)。フォルダのエントリも同じ規則で書く。

- Zip内のエントリ名だけを変える。ワークフォルダや元ファイルは変更しない。
- 変更前後の名前を記録し、完了時に通知する。
- 「自動」ではこの処理をしない(すべてUTF-8)。
- トレードオフ: 名前が壊れない代わりに、UTF-8フラグを無視する古いツールでは、UTF-8で書いた名前だけが化ける。`_` に置き換える案は、この問題は無いが、元の名前が失われるため採用しなかった。
- 将来の案(未決事項): 7-Zipは、Shift_JISの名前にUnicodeパス拡張フィールド(0x7075)も付ける。付ければ、読む側がこれを解釈するツール(7-Zip、Info-ZIP unzip、`zip` クレートなど)で、文字コードを推測せずに済む。

### 6.2 Shift_JIS名の書き込み(検証済み)

`prototypes/sjis-zip-writer/` で検証した(2026-11-04、macOS / `zip` 9.3.0)。

**結果: UTF-8フラグなしでShift_JIS名を書ける。**

- `zip` クレートは、`FileOptions::name(&[u8])` で**生のバイト列**を名前に指定でき、`start_file_with_options` で書き込める。
- 自作パーサでセントラルディレクトリを直接読み、UTF-8フラグ(bit11)が**立っていない**こと、名前がShift_JISのバイト列そのものであることを確認した(暗号化なし / ZipCrypto / AES-256の3種すべて)。
- Pythonの `zipfile` でも、bit11なしの名前をcp932として正しく読めた。
- 濁点分離(NFD)の名前を、NFC正規化してからShift_JISに変換する流れも動作した(`か゛き゛` → `がぎ`)。

**⚠ 落とし穴: フラグが誤って立つことがある**

`zip` クレートは、名前のバイト列が「UTF-8として正しく、かつ非ASCII」なら、UTF-8フラグを自動で立てる。Shift_JISのバイト列が偶然UTF-8として正しい場合に、誤ってフラグが立つ。

- 実例: 半角カナ `ﾃｱ`(Shift_JISで `C3 B1`)は、UTF-8の `ñ` として正しいため、フラグが立ってしまった。
- 影響: Windowsが、Shift_JISの名前をUTF-8として読んで文字化けする。
- 対策: Zipの書き込み完了後に、**全エントリのUTF-8フラグを、ローカルヘッダとセントラルヘッダの両方で落とす後処理**を行う(`clear_utf8_flag`)。検証で、暗号化なし / ZipCrypto / AES-256のいずれも、後処理後に正しく読み戻せることを確認した。
- 制限: プロトタイプは、Zip64(ローカルヘッダ位置が `0xFFFFFFFF`)のエントリに未対応。本実装では、Zip64の場合の位置の取り方も実装する。
- 後処理で落とすのは、**Shift_JISで書いたエントリだけ**。UTF-8で書いたエントリ(Shift_JISに変換できなかった名前)は、`zip` クレートが自動で立てたフラグをそのまま残す(7-Zipと同じ)。そのため、後処理には「何番目のエントリがShift_JISか」の一覧を渡す(書き込み順 = セントラルディレクトリの順)。「自動」モードでは、この後処理は行わない。

**Shift_JISに変換できない文字(`encoding_rs` の結果)**

| 文字 | 結果 | 備考 |
|---|---|---|
| ひらがな・カタカナ・半角カナ | 変換できる | |
| `～`(U+FF5E 全角チルダ) | 変換できる | |
| **`〜`(U+301C 波ダッシュ)** | **変換できない** | **Macで作ったファイル名に出やすい** |
| `－`(U+FF0D)、`−`(U+2212) | 変換できる(どちらも `81 7C`) | |
| ①、㈱、Ⅲ、㎏(NEC特殊文字) | 変換できる | |
| 髙、﨑(IBM拡張) | 変換できる | |
| 絵文字、ハングル | 変換できない | その名前だけUTF-8フラグ付きで書く(6.1) |

- 波ダッシュ `〜` は、WindowsのCP932では全角チルダ `～` に対応する。そのため、**先に `～` に置き換えて、Shift_JISで保存できるようにする**(6.1)。7-Zipは置き換えずにUTF-8で書くが、ここでは、より多くの名前をShift_JISに保てる、この方針を採る。

### 6.3 暗号化

| 方式 | 実装 | 備考 |
|---|---|---|
| ZipCrypto | `zip::unstable::write::FileOptionsExt::with_deprecated_encryption` | 初期値。書き込み・復号とも検証済み |
| AES-256 | `FileOptions::with_aes_encryption(AesMode::Aes256, ...)`(`aes-crypto` 機能、標準で有効) | 書き込み・復号とも検証済み |

- 空のパスワードでの暗号化はエラーになるため、パスワード未入力のときは暗号化しない(要件どおり)。
- macOS標準の `unzip` は、AES-256のZipを「v5.1が必要」として拒否する(想定どおり)。AES-256を選ぶ場合は、受け取る側にKekaや7-Zipが必要になる旨を、画面で注意書きする。

- パスワード未入力なら、暗号化しない。
- パスワードは、メモリ上でのみ扱い、ログや一時ファイルに残さない。

### 6.4 その他の書き込み設定

- 圧縮方式: Deflate。
- **Zip64** に対応する(4GBを超えるファイルに備える)。
- 更新日時は元ファイルのものを引き継ぐ。
- Unixのパーミッションを保存する(要検証)。
- 書き込みは、保存先に**一時ファイル名**で出力し、完了したら正式名にリネームする。キャンセル・エラー時に、中途半端なZipが残らない。
- シンボリックリンクは、ワークフォルダへのコピー前に検出して拒否する(4章)。

## 7. フロントエンド

- 状態管理: 画面仕様の状態(初期 / 圧縮 / 解凍 / 処理中 / 完了)を、状態機械として実装する。
- ドロップ: Tauriの**ドラッグ&ドロップイベント**でパスを受け取る(HTML5のドロップでは、実ファイルパスが取れないため)。
- ダイアログ: 同名確認・パスワード・文字コード選択は、アプリ内のモーダルで実装する。保存先指定は `tauri-plugin-dialog` のOSダイアログを使う。
- ダーク/ライト: CSSの `prefers-color-scheme` でOSの設定に合わせる。
- ウィンドウサイズ: `tauri.conf.json` で、初期サイズ・最小サイズとも 480×400 を設定する。
- フレームワーク: **Svelte 5 + TypeScript**(ビルドツールはVite)。**SvelteKitは使わない**(画面が1つでルーティング不要なため。テンプレートのSvelteKitから、素のSvelte + Viteへ切り替えた)。画面が1つで小さく、状態の切り替えが中心のため、コンパイル時に最適化されるSvelteが向いている。

## 8. ビルド・開発環境

- 現在の開発機(macOS)には、Rust(`cargo`、`rustc`)が**未インストール**。`rustup` で導入する。Node.js は v24 が入っている。
- Windows版は、**Windows上でビルド**する(クロスコンパイルはしない)。方法は、Windows機での手元ビルド、またはGitHub Actionsのどちらか(6章で決める)。Windowsでは、MSVCビルドツールとWebView2が必要。
- 配布時のコード署名・公証(macOSのNotarization、Windowsの署名)は、個人利用なら当面不要。配布を考えるなら、別途検討する。

- **単体テスト(Rust)**:

  - 連番の付与(同名フォルダ)

```
uni-zipper/
├── README.md
├── LICENSE
├── .gitignore
├── docs/                      # 設計書
├── src/                       # フロントエンド(Svelte + TypeScript)

│   ├── src/                   # 3章のモジュール
│   └── tests/fixtures/        # テスト用のZip(Shift_JIS、NFDなど)
└── prototypes/                # 検証用(本体のビルドとは無関係)
    └── sjis-zip-writer/       # Shift_JIS名の書き込み検証
        ├── Cargo.toml
        └── src/main.rs
```

- `src/` と `src-tauri/` は、Tauriの標準の配置(`create-tauri-app` が作る形)。
- `prototypes/` 配下は、**独立したCargoプロジェクト**とし、`src-tauri` の依存やビルドに影響させない。
- `prototypes/` は、検証が終わっても**削除せず残す**。検証結果は `docs/` に書く。
- `.gitignore` には、`target/`、`node_modules/`、`dist/` などを入れる。
