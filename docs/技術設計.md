# uni-zipper 技術設計

> ステータス: ドラフト。要件は [機能要件.md](機能要件.md)、画面は [画面仕様.md](画面仕様.md) を参照。
> 「要検証」は、実装前または実装中にライブラリの挙動を確認する項目。

## 1. 全体構成

- **Tauri 2** を使う。
- **バックエンド(Rust)**: Zipの読み書き、文字コード判定・変換、正規化、ワークフォルダ管理、進捗通知、キャンセル。
- **フロントエンド**: 画面の状態管理、ドロップ受付、ダイアログ表示。Zipの処理はすべてRust側で行う。
- 処理は重いので、Rust側のコマンドは別スレッド(`spawn_blocking`)で実行し、UIを止めない。

```
[フロントエンド]                         [Rust]
 ドロップ(Tauriのドラッグ&ドロップイベント) ──パス一覧──→ add_items / inspect_zip
 保存ボタン ──────────────────────────→ compress(options)
 解凍ボタン ──────────────────────────→ extract(options)
 キャンセル ──────────────────────────→ cancel()
 ←──────── 進捗・完了・エラー(Channel / イベント) ────────
```

| 用途 | クレート | バージョン | 備考 |
|---|---|---|---|
| アプリ基盤 | `tauri` | 2.12.x | |
| 保存ダイアログ | `tauri-plugin-dialog` | 2.8.x | 保存先指定、メッセージ表示 |
| Zip読み書き | `zip` | 9.3.x | Shift_JIS名・ZipCrypto・AES-256の書き込みと復号を検証済み(6章) |
| 文字コード変換 | `encoding_rs` | 0.8.x | Shift_JIS(CP932相当)の変換 |
| 正規化(NFC/NFD) | `unicode-normalization` | 0.1.x | |
| ディレクトリ走査 | `walkdir` | 2.5.x | フォルダのコピー、一覧化 |

- 文字コードの自動判定ライブラリ(`chardetng` など)は、**使わない**。候補はShift_JISとUTF-8の2つだけなので、バイト列の妥当性チェックのほうが確実で、結果も説明しやすい。


## 4. ワークフォルダ

- 場所: OSの一時ディレクトリ配下に、アプリ専用のディレクトリ + 実行ごとの一意なサブディレクトリを作る。
- 追加: ドロップされたパスを、ワークフォルダへコピーする(フォルダは再帰コピー)。
- **シンボリックリンクの拒否**: コピーを始める前に、ドロップされた全パスを `walkdir`(リンクを辿らない設定)で走査し、シンボリックリンクが1つでもあれば、**何もコピーせずに全体を拒否**する(途中まで追加された状態を作らない)。
- 同名の判定: ワークフォルダ直下の名前で行う。確認の結果は、上書き / 自動連番リネーム / キャンセル。
- 削除タイミング: 圧縮完了時、キャンセル時、エラー時、クリア時。
- **掃除**: アプリ起動時に、前回の異常終了などで残ったワークフォルダを削除する。
  - 場所は `<OSの一時ディレクトリ>/uni-zipper/run-<PID>-<時刻>`。
  - 別の起動(複数ウィンドウ)が使用中のものを消さないよう、**更新から24時間以上経ったもの**だけを削除する(自分のワークフォルダは対象外)。
- **実装**: `src-tauri/src/workdir.rs`。主なAPIは次のとおり。
  - `WorkDir::check_no_symlinks(paths)`: 全パスを走査し、リンクが1つでもあれば `SymlinkRejected`。ドロップ全体の拒否に使う(`add` でも自分の分を再検査する)。
  - `WorkDir::exists(name)` → 同名があれば、画面で上書き / リネーム / キャンセルを選ばせる。
  - `WorkDir::add(src, ConflictPolicy::{Overwrite, Rename})` → 最終的な名前を返す。途中で失敗したらコピーしかけたものを削除する。
  - `WorkDir::list()` / `remove(name)` / `clear()`、`Drop` で削除。
  - 連番は、ファイルは拡張子の前(`file_1.txt`、`archive.tar_1.gz`)、フォルダは末尾(`folder_1`)に付ける。先頭のドットは拡張子とみなさない(`.bashrc_1`)。
- 圧縮時は、ワークフォルダ内のフラットな内容をそのままZipにする。

## 5. 解凍の設計

### 5.1 エントリ名の解決

Zipのファイル名は、次の優先順位で決める。

1. エントリにUTF-8フラグ(一般目的ビット11)が立っている → **UTF-8**として確定。
2. Unicodeパス拡張フィールド(0x7075)がある → その値を採用(要検証: `zip` クレートの対応状況)。
3. どちらもない → 生のバイト列(`name_raw` 相当)から、下の判定を行う。

### 5.2 判定ロジック(フラグなしの場合)

全エントリのバイト列について、次の2つを試す。

| UTF-8として正しい | Shift_JISとして正しい | 結果 |
|---|---|---|
| はい | いいえ | UTF-8で確定 |
| いいえ | はい | Shift_JISで確定 |
| はい | はい(かつ非ASCIIあり) | **曖昧** → プレビューで選ばせる |
| いいえ | いいえ | **曖昧**(読めない)→ プレビューで選ばせる(両方「化けた表示」になるので注意書きを添える) |
| 全部ASCII | - | 変換不要 |

- ファイル名の途中で一部のエントリだけ違うケースは、まれなので考慮しない(全エントリで1つの文字コードを選ぶ)。
- Shift_JISは、`encoding_rs` の `SHIFT_JIS`(WHATWG仕様ではCP932相当のWindows-31J拡張)を使う。①②などのNEC特殊文字、丸数字、機種依存文字も読める。
- プレビューには、先頭数件のファイル名を、両方の読み方で表示する。

### 5.3 ファイル名の変換と正規化

- デコード後のファイル名を、**WindowsでもmacOSでもNFCに正規化**する(APFSはNFCでも問題なく扱える)。
- 展開先での無害化:
  - パス区切りは `/` に統一する。
  - **Zip Slip対策**: `..` や絶対パスを含むエントリは、展開先の外に出ないように検査し、危険なものはスキップする(スキップ一覧に載せる)。
  - Windowsで使えない文字(`: * ? " < > |`)や予約名(`CON` など)、末尾のドット・空白は、`_` に置き換える。置き換えたファイルは、完了時にスキップ一覧と同じ形式で通知する。
  - 正規化や置き換えの結果、同名になったら連番を付ける。
- 除外ファイル(`.DS_Store`、`__MACOSX`、`Thumbs.db`、`desktop.ini`)は、名前の判定で展開しない。`__MACOSX` はディレクトリごと除外する。

### 5.4 展開先フォルダ

- 場所: Zipと同じディレクトリ。
- 名前: Zipの拡張子を除いた名前。既にあれば `_1`、`_2` を付ける。
- 作成は、展開開始時に行う。キャンセル・エラー時は削除する。

### 5.5 パスワード付きZip

- **ドロップ時の判定**: セントラルディレクトリの暗号化フラグ(ビット0)、またはAESの拡張フィールドで判定する。
- 解凍時に、パスワードを使って復号する。
- **パスワード誤りの検出**:
  - AES: 検証値により、ほぼ確実に検出できる。
  - ZipCrypto: ヘッダの検証が1バイトだけなので、約1/256の確率で誤ったパスワードを通してしまう。**展開後のCRC32不一致も「パスワード誤り」として扱う**。
- 3回失敗で中止(画面仕様どおり)。

### 5.6 進捗・キャンセル・スキップ

- 進捗は、展開した総バイト数 / 全体の総バイト数(非圧縮サイズ)で計算する。
- キャンセルは、共有の `AtomicBool` を、ファイルごと、および一定バイト(例: 1MB)ごとに確認する。
- 読み書きできないファイルは、スキップして続行し、名前を記録する。完了時にまとめて通知する。

## 6. 圧縮の設計

### 6.1 エントリ名

| 圧縮先OS | 名前のエンコード | UTF-8フラグ | 正規化 |
|---|---|---|---|
| 自動 | UTF-8 | 立てる | NFC |
| Windows | Shift_JIS(CP932) | **立てない** | NFC |

- 「Windows」の場合、保存ボタン押下時に、全エントリ名をShift_JISへ変換できるか検査する。
  - **波ダッシュ `〜`(U+301C)は、先に全角チルダ `～`(U+FF5E)へ置き換える**(CP932で対応する文字。Macで作った名前に出やすい)。この置き換えは、変換できない文字の検査より前に行う。
  - それでも変換できない文字(絵文字、ハングルなど)は `_` に置き換える。置き換えるのは**Zip内のエントリ名だけ**で、ワークフォルダや元ファイルは変更しない。
  - 置き換えた結果が同名になった場合は、`_1`、`_2` の連番を付ける。
  - 変更前後の名前を記録し、完了時に通知する。
  - 検査は「Windows」のときだけ行う(「自動」はUTF-8なので不要)。

### 6.2 Shift_JIS名の書き込み(検証済み)

`prototypes/sjis-zip-writer/` で検証した(2026-11-04、macOS / `zip` 9.3.0)。

**結果: UTF-8フラグなしでShift_JIS名を書ける。**

- `zip` クレートは、`FileOptions::name(&[u8])` で**生のバイト列**を名前に指定でき、`start_file_with_options` で書き込める。
- 自作パーサでセントラルディレクトリを直接読み、UTF-8フラグ(bit11)が**立っていない**こと、名前がShift_JISのバイト列そのものであることを確認した(暗号化なし / ZipCrypto / AES-256の3種すべて)。
- Pythonの `zipfile` でも、bit11なしの名前をcp932として正しく読めた。
- 濁点分離(NFD)の名前を、NFC正規化してからShift_JISに変換する流れも動作した(`か゛き゛` → `がぎ`)。

**⚠ 落とし穴: フラグが誤って立つことがある**

`zip` クレートは、名前のバイト列が「UTF-8として正しく、かつ非ASCII」なら、UTF-8フラグを自動で立てる。Shift_JISのバイト列が偶然UTF-8として正しい場合に、誤ってフラグが立つ。

- 実例: 半角カナ `ﾃｱ`(Shift_JISで `C3 B1`)は、UTF-8の `ñ` として正しいため、フラグが立ってしまった。
- 影響: Windowsが、Shift_JISの名前をUTF-8として読んで文字化けする。
- 対策: Zipの書き込み完了後に、**全エントリのUTF-8フラグを、ローカルヘッダとセントラルヘッダの両方で落とす後処理**を行う(`clear_utf8_flag`)。検証で、暗号化なし / ZipCrypto / AES-256のいずれも、後処理後に正しく読み戻せることを確認した。
- 制限: プロトタイプは、Zip64(ローカルヘッダ位置が `0xFFFFFFFF`)のエントリに未対応。本実装では、Zip64の場合の位置の取り方も実装する。
- 「Windows」モードでは、すべてのエントリがShift_JISなので、全エントリのフラグを落としてよい。「自動」モードでは、この後処理は行わない。

**Shift_JISに変換できない文字(`encoding_rs` の結果)**

| 文字 | 結果 | 備考 |
|---|---|---|
| ひらがな・カタカナ・半角カナ | 変換できる | |
| `～`(U+FF5E 全角チルダ) | 変換できる | |
| **`〜`(U+301C 波ダッシュ)** | **変換できない** | **Macで作ったファイル名に出やすい** |
| `－`(U+FF0D)、`−`(U+2212) | 変換できる(どちらも `81 7C`) | |
| ①、㈱、Ⅲ、㎏(NEC特殊文字) | 変換できる | |
| 髙、﨑(IBM拡張) | 変換できる | |
| 絵文字、ハングル | 変換できない | `_` に置き換える |

- 波ダッシュ `〜` は、WindowsのCP932では全角チルダ `～` に対応する。そのため、`_` ではなく `～` に置き換える(6.1で決定済み)。

### 6.3 暗号化

| 方式 | 実装 | 備考 |
|---|---|---|
| ZipCrypto | `zip::unstable::write::FileOptionsExt::with_deprecated_encryption` | 初期値。書き込み・復号とも検証済み |
| AES-256 | `FileOptions::with_aes_encryption(AesMode::Aes256, ...)`(`aes-crypto` 機能、標準で有効) | 書き込み・復号とも検証済み |

- 空のパスワードでの暗号化はエラーになるため、パスワード未入力のときは暗号化しない(要件どおり)。
- macOS標準の `unzip` は、AES-256のZipを「v5.1が必要」として拒否する(想定どおり)。AES-256を選ぶ場合は、受け取る側にKekaや7-Zipが必要になる旨を、画面で注意書きする。

- パスワード未入力なら、暗号化しない。
- パスワードは、メモリ上でのみ扱い、ログや一時ファイルに残さない。

### 6.4 その他の書き込み設定

- 圧縮方式: Deflate。
- **Zip64** に対応する(4GBを超えるファイルに備える)。
- 更新日時は元ファイルのものを引き継ぐ。
- Unixのパーミッションを保存する(要検証)。
- 書き込みは、保存先に**一時ファイル名**で出力し、完了したら正式名にリネームする。キャンセル・エラー時に、中途半端なZipが残らない。
- シンボリックリンクは、ワークフォルダへのコピー前に検出して拒否する(4章)。

## 7. フロントエンド

- 状態管理: 画面仕様の状態(初期 / 圧縮 / 解凍 / 処理中 / 完了)を、状態機械として実装する。
- ドロップ: Tauriの**ドラッグ&ドロップイベント**でパスを受け取る(HTML5のドロップでは、実ファイルパスが取れないため)。
- ダイアログ: 同名確認・パスワード・文字コード選択は、アプリ内のモーダルで実装する。保存先指定は `tauri-plugin-dialog` のOSダイアログを使う。
- ダーク/ライト: CSSの `prefers-color-scheme` でOSの設定に合わせる。
- ウィンドウサイズ: `tauri.conf.json` で、初期サイズ・最小サイズとも 480×400 を設定する。
- フレームワーク: **Svelte 5 + TypeScript**(ビルドツールはVite)。**SvelteKitは使わない**(画面が1つでルーティング不要なため。テンプレートのSvelteKitから、素のSvelte + Viteへ切り替えた)。画面が1つで小さく、状態の切り替えが中心のため、コンパイル時に最適化されるSvelteが向いている。

## 8. ビルド・開発環境

- 現在の開発機(macOS)には、Rust(`cargo`、`rustc`)が**未インストール**。`rustup` で導入する。Node.js は v24 が入っている。
- Windows版は、**Windows上でビルド**する(クロスコンパイルはしない)。方法は、Windows機での手元ビルド、またはGitHub Actionsのどちらか(6章で決める)。Windowsでは、MSVCビルドツールとWebView2が必要。
- 配布時のコード署名・公証(macOSのNotarization、Windowsの署名)は、個人利用なら当面不要。配布を考えるなら、別途検討する。

## 9. テスト方針

- **単体テスト(Rust)**:
  - 文字コード判定(UTF-8のみ / Shift_JISのみ / 曖昧 / 全ASCII)
  - NFC/NFD変換(濁点・半濁点)
  - 除外ファイルの判定
  - Zip Slipの検出
  - 連番の付与(同名フォルダ)
- **結合テスト**: 次のZipを、実物のテストデータとして用意し、解凍結果を検証する。
  - Windows標準機能で作成したZip(Shift_JIS)
  - macOSのアーカイブユーティリティで作成したZip(UTF-8、NFD)
  - 7-ZipでUTF-8フラグ付きで作成したZip
  - ZipCrypto、AES-256のパスワード付きZip
- **ラウンドトリップ**: 圧縮 → 他OSの標準機能で開いて、化けないことを目視確認。

- `prototypes/` は、検証が終わっても**削除せず残す**。検証結果は `docs/` に書く。
- `.gitignore` には、`target/`、`node_modules/`、`dist/` などを入れる。
